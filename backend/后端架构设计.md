# A股分位观测站：Vue + FastAPI + MySQL 后端架构设计

## 1. 技术方案

项目采用前后端分离架构：

```text
Vue 前端
    -> FastAPI 接口服务
    -> MySQL 数据库

宝塔计划任务
    -> 独立 Python 爬虫
    -> MySQL 数据库
```

各部分职责：

- Vue：负责页面展示、图表和用户交互。
- FastAPI：只提供查询接口，不负责抓取外部数据。
- crawler：定时请求丹卷基金接口，校验后写入数据库。
- MySQL：保存指数基本信息和每日估值历史。
- 宝塔计划任务：定时执行爬虫。

Web 服务和爬虫相互独立：爬虫失败不影响历史数据查询，Web 服务重启也不会触发抓取任务。

## 3. 数据库设计

当前数据库只需要两张业务表：

```text
index_info
    1
    |
    | index_code
    |
    N
index_valuation
```

### `index_info`

保存指数基本信息：

```text
id
index_code
index_name
```

当前三条数据：

```text
SH000300 / 沪深300
SH000905 / 中证500
SZ399006 / 创业板
```

### `index_valuation`

保存每日估值百分位：

```text
id
index_code
data
pe_percentile
pb_percentile
```

其中：

- `data` 是完整业务日期，例如 `2026-09-08`。
- 百分位保存为 `0` 到 `1` 的小数，例如 `0.6888`。
- `(index_code, data)` 是唯一约束。
- 同一指数同一天重复抓取时更新原记录，不新增重复数据。

数据库初始化使用 `backend/init.sql`。Web 服务和爬虫均不应在启动时自动建表，生产环境由 Navicat 或部署脚本先完成建库。

## 4. 公共数据库配置

`backend/common/db_config.py` 负责数据库连接，Web 和 crawler 都可以导入它。建议只通过环境变量提供配置：

```text
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=cn_index_percentile_app
DB_PASSWORD=数据库密码
DB_NAME=cn_index_percentile
```

不要把密码写进 Python 文件、Git 仓库或公开网站目录。

更安全的生产配置是拆分数据库账号：

```text
crawler 账号：SELECT、INSERT、UPDATE
web 账号：SELECT
```

如果先使用一个账号，也应只授予 `cn_index_percentile` 数据库范围内的权限，不使用 root。

生产环境建议环境变量文件放在项目目录外，例如：

```text
/www/wwwroot/www.11251236.xyz/config/db.env
```

权限设置：

```bash
chmod 600 /www/wwwroot/www.11251236.xyz/config/db.env
```

宝塔计划任务执行爬虫前加载该文件：

```bash
cd /www/wwwroot/www.11251236.xyz/personal-website/backend
. /www/wwwroot/www.11251236.xyz/config/db.env
/www/wwwroot/www.11251236.xyz/personal-website/backend/.venv/bin/python -m crawler.fetch_val
```

## 5. FastAPI 接口设计

FastAPI 只查询 MySQL，不请求丹卷基金接口，也不写入估值数据。

建议接口：

| 方法  | 路径                                  | 用途                       |
| ----- | ------------------------------------- | -------------------------- |
| `GET` | `/api/health`                         | 检查服务和数据库是否可用   |
| `GET` | `/api/indices`                        | 查询指数列表               |
| `GET` | `/api/valuations/latest`              | 查询三个指数的最新数据     |
| `GET` | `/api/valuations/{index_code}`        | 查询指定指数历史数据       |
| `GET` | `/api/valuations/{index_code}/latest` | 查询指定指数最新数据       |
| `GET` | `/api/valuations/date/{data}`         | 查询指定日期的三大指数数据 |

### 推荐响应内容

`GET /api/valuations/latest`：

```json
[
  {
    "index_code": "SH000300",
    "index_name": "沪深300",
    "data": "2026-09-08",
    "pe_percentile": 0.6888,
    "pb_percentile": 0.4216
  }
]
```

后端返回小数，Vue 前端负责格式化成百分比：

```text
0.6888 -> 68.88%
```

### 查询历史时的参数

可以支持：

```text
GET /api/valuations/SH000300?start_date=2026-01-01&end_date=2026-09-08
```

参数建议：

- `start_date`：开始日期，可选。
- `end_date`：结束日期，可选。
- `limit`：最大返回条数，可选，设置合理上限。

后端必须校验 `index_code` 是否存在，日期格式是否为 `YYYY-MM-DD`，避免直接拼接 SQL 字符串。

## 6. 爬虫职责

`backend/crawler/fetch_val.py` 负责：

1. 请求 `https://danjuanfunds.com/djapi/index_eva/dj`。
2. 校验 `result_code == 0`。
3. 按 `index_code` 筛选三大指数。
4. 使用 `ts` 转换上海时区的完整日期，写入 `data`。
5. 校验三个指数都存在。
6. 校验 `pe_percentile` 和 `pb_percentile` 都是 `0` 到 `1` 之间的有效数值。
7. 在一个事务中写入或更新三条记录。
8. 任一条失败时回滚全部写入。
9. 成功或失败都输出日志，并使用非零退出码表示失败。

推荐执行链路：

```text
请求接口
  -> 校验 JSON 结构和 result_code
  -> 按 index_code 提取三大指数
  -> ts 转换为 data
  -> 校验百分位和日期一致性
  -> 开启事务
  -> 写入 index_info
  -> UPSERT index_valuation
  -> 提交事务
  -> 输出结果
```

## 8. 部署方式

### 爬虫

爬虫不是常驻服务，由宝塔计划任务调用：

```bash
cd /www/wwwroot/www.11251236.xyz/personal-website/backend
. .env
/www/wwwroot/www.11251236.xyz/personal-website/backend/.venv/bin/python -m crawler.fetch_val >> /www/wwwroot/www.11251236.xyz/personal-website/logs/crawler/fetch-$(date +\%F).log 2>&1
```

建议：

- 每日 22:00 执行主任务。
- 每日 23:00 执行补偿任务。
- 两次执行都使用相同的数据库幂等逻辑。
- 宝塔 cron 中 `%` 要写成 `\%`。

### FastAPI

开发环境：

```bash
cd backend
uvicorn web.main:app --host 127.0.0.1 --port 8000 --reload
```

生产环境可由宝塔进程守护、Systemd 或 Gunicorn/Uvicorn 管理。Nginx 对外提供域名和 HTTPS，再反向代理到 FastAPI：

```text
浏览器 -> Nginx -> FastAPI 127.0.0.1:8000 -> MySQL
```

FastAPI 不应直接暴露 MySQL 端口，也不建议让 MySQL 监听公网地址。

## 9. 开发顺序

### 第一阶段：后端基础

1. 按 `init.sql` 建立数据库表。
2. 整理 `backend/common/db_config.py`。
3. 将现有爬虫迁移到 `backend/crawler/fetch_val.py`。
4. 用 `--dry-run` 验证接口解析。
5. 使用测试库验证重复执行和事务回滚。

### 第二阶段：FastAPI 查询接口

1. 创建 `web/main.py`。
2. 创建数据库依赖和 Pydantic 响应模型。
3. 实现健康检查、指数列表、最新数据和历史数据接口。
4. 增加 CORS，仅允许 Vue 前端开发地址和生产域名。
5. 统一错误响应格式。

### 第三阶段：Vue 前端

1. 请求 `/api/indices` 展示三个指数。
2. 请求 `/api/valuations/latest` 展示最新 PE/PB 百分位。
3. 请求历史接口绘制趋势图。
4. 增加日期筛选和指数切换。
5. 处理接口加载、空数据和错误状态。

## 10. 关键原则

- FastAPI 负责读，crawler 负责写。
- 数据库是主数据源，CSV 只作为可选导出或备份。
- 业务筛选使用 `index_code`，不使用接口 `id`。
- 数据库日期列使用 `data`，保存完整日期。
- 百分位保存小数，不保存带 `%` 的字符串。
- 爬虫写入必须使用 `(index_code, data)` 幂等更新。
- Web 和 crawler 尽量使用不同数据库账号。
- 密码放在受限环境变量文件中，不进入 Git。
- 数据库不暴露公网，FastAPI 通过内网或本机访问数据库。
