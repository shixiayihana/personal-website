# A股分位观测站：数据来源、字段和建表说明

## 1. 数据来源

项目调用的接口是：

```text
https://danjuanfunds.com/djapi/index_eva/dj
```

接口返回的指数数据位于 `data.items`。接口一次返回多个指数，目前项目只关注以下三个指数：

| 指数名称 | `index_code` | 接口示例 `id` |
| -------- | ------------ | ------------: |
| 沪深300  | `SH000300`   |        516436 |
| 中证500  | `SH000905`   |        516437 |
| 创业板   | `SZ399006`   |        516441 |

程序应使用 `index_code` 筛选指数，不建议使用接口 `id` 或 `name` 作为主要筛选条件。

- `index_code`：稳定的指数代码，用于关联两张表和筛选数据。
- 接口 `id`：数据源对象编号。本项目当前精简建表，不保存该字段。
- 数据库 `id`：本地自增主键，与接口 `id` 完全不同。
- `name`：指数名称，用于展示，保存到 `index_info.index_name`。

## 2. 数据库表设计

本项目采用两张表：

```text
index_info
    1
    |
    | index_code
    |
    N
index_valuation
```

### 2.1 `index_info` 指数基本信息表

一条记录代表一个指数，保存不随每日估值变化的基本信息。

| 列名         | 类型                             | 说明                      |
| ------------ | -------------------------------- | ------------------------- |
| `id`         | `BIGINT UNSIGNED AUTO_INCREMENT` | 数据库自增主键            |
| `index_code` | `VARCHAR(16)`                    | 指数代码，例如 `SH000300` |
| `index_name` | `VARCHAR(32)`                    | 指数名称，例如“沪深300”   |

约束：

```sql
UNIQUE KEY uk_index_code (index_code)
```

### 2.2 `index_valuation` 每日估值历史表

一条记录代表一个指数在某一天的估值百分位数据。

| 列名            | 类型                             | 说明                                      |
| --------------- | -------------------------------- | ----------------------------------------- |
| `id`            | `BIGINT UNSIGNED AUTO_INCREMENT` | 数据库自增主键                            |
| `index_code`    | `VARCHAR(16)`                    | 指数代码，关联 `index_info.index_code`    |
| `data`          | `DATE`                           | 估值数据对应的完整日期，例如 `2026-09-08` |
| `pe_percentile` | `DECIMAL(8,6)`                   | PE历史百分位，保存为 `0.6888`             |
| `pb_percentile` | `DECIMAL(8,6)`                   | PB历史百分位，保存为 `0.4216`             |

约束：

```sql
UNIQUE KEY uk_index_data (index_code, data)
```

同一个指数同一天只能有一条记录。重复抓取同一天数据时，应更新原记录，而不是新增重复记录。

## 3. 为什么日期列使用 `data`

本项目将每日估值表的日期列命名为 `data`，含义是“这条估值数据对应的日期”，例如：

```text
data = 2026-09-08
```

接口返回的 `date` 字段只有 `09-08`，缺少年份，不适合直接作为数据库长期日期。写入数据库前，应根据接口的 `ts` 毫秒时间戳转换为完整的 `YYYY-MM-DD` 日期，并写入 `data`。

`data` 是业务日期，不是程序抓取时间。当前精简设计不保存抓取时间，因为网站只需要展示每日估值历史。

## 4. 接口字段到数据库字段的映射

| 接口字段        | 数据库字段                                             | 处理方式                     |
| --------------- | ------------------------------------------------------ | ---------------------------- |
| `index_code`    | `index_info.index_code` / `index_valuation.index_code` | 原样保存，用于识别和关联指数 |
| `name`          | `index_info.index_name`                                | 保存指数名称                 |
| `ts`            | `index_valuation.data`                                 | 将毫秒时间戳转换为完整日期   |
| `pe_percentile` | `index_valuation.pe_percentile`                        | 保存原始小数，例如 `0.6888`  |
| `pb_percentile` | `index_valuation.pb_percentile`                        | 保存原始小数，例如 `0.4216`  |

其他接口字段，例如 `pe`、`pb`、`roe`、`peg`、`eva_type`、`url`、`source` 等，当前不属于网站核心展示需求，因此暂不保存。以后需要估值解释、数据追溯或更复杂的分析时，再增加列即可。

## 5. 三个指数的示例数据

| `index_code` | `index_name` | `data`         | `pe_percentile` | `pb_percentile` |
| ------------ | ------------ | -------------- | --------------: | --------------: |
| `SH000300`   | 沪深300      | 根据 `ts` 转换 |          0.6888 |          0.4216 |
| `SH000905`   | 中证500      | 根据 `ts` 转换 |          0.7764 |          0.7752 |
| `SZ399006`   | 创业板       | 根据 `ts` 转换 |          0.3240 |          0.6084 |

页面展示时格式化为百分比：

```text
沪深300：PE 68.88%，PB 42.16%
中证500：PE 77.64%，PB 77.52%
创业板：PE 32.40%，PB 60.84%
```

数据库保存小数，不要保存带 `%` 的字符串，以便后续排序、筛选和绘图。

## 6. 查询示例

查询三大指数最新数据：

```sql
SELECT
    v.data,
    i.index_code,
    i.index_name,
    v.pe_percentile,
    v.pb_percentile
FROM index_valuation AS v
JOIN index_info AS i
    ON v.index_code = i.index_code
ORDER BY v.data DESC, i.id;
```

查询某一天的数据：

```sql
SELECT
    i.index_name,
    v.pe_percentile,
    v.pb_percentile
FROM index_valuation AS v
JOIN index_info AS i
    ON v.index_code = i.index_code
WHERE v.data = '2026-09-08'
ORDER BY i.id;
```

## 7. Navicat 执行顺序

1. 在 Navicat 中打开已经创建好的 `cn_index_percentile` 数据库。
2. 打开项目中的 `init.sql`。
3. 确认脚本中的数据库名称与 Navicat 中的数据库名称一致。
4. 执行整个脚本。
5. 刷新数据库，确认出现 `index_info` 和 `index_valuation` 两张表。
6. 查看 `index_info`，确认已有沪深300、中证500、创业板三条记录。

如果旧版脚本已经创建了 `index_percentile_daily`，新版脚本不会自动删除它。确认旧表没有需要保留的数据后，再由 Navicat 手动备份或删除旧表，避免新旧结构混淆。

## 8. 结论

当前最精简且满足需求的数据库结构是：

```text
index_info
    id
    index_code
    index_name

index_valuation
    id
    index_code
    data
    pe_percentile
    pb_percentile
```

其中：

- `index_info` 管理三大指数的基本信息。
- `index_valuation` 管理每日历史估值百分位。
- `data` 是完整业务日期。
- `pe_percentile` 和 `pb_percentile` 是网站的核心展示数据。
- `(index_code, data)` 保证同一指数同一天不会重复写入。
